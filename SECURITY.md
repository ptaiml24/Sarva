# Security policy

Thank you for helping keep Sarva and its users safe.

## Reporting a vulnerability

Please **do not** open a public GitHub issue for unfixed security problems.

Instead, use **one** of these channels:

1. **GitHub** — If the repository has [private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability) enabled: use **Security → Report a vulnerability**.
2. **Maintainer email** — If you know the maintainer’s security contact from the repo or documentation, send details there with a descriptive subject line (e.g. `[Sarva security]`).

Include: affected component (API / web / etc.), reproduction steps if possible, and impact you believe applies. Assume good-faith disclosures will be acknowledged when received.

## Scope

This policy applies to the Sarva codebase in this repository as shipped (API, web UI, tooling). Reports about third-party dependencies may be routed to upstream projects after triage.

## Supported versions / expectations

Until a formal versioning policy exists, fixes are aimed at **`main`** (or the default development branch). This is an early-stage control-plane demonstrator—not a turnkey production security program. See the root **`README.md`** disclaimer for architectural and operational limitations.
